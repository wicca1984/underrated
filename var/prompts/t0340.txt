## Task (t0340, milestone MS-NewTargets / Wiki tables): map the legacy `<table border="N">` HTML presentational attribute to CSS borders.

### Background (verified by the orchestrator)
- CSS borders on tables/cells ALREADY paint correctly (e.g. `<td style="border:1px solid black">` draws gridlines).
- The gap is ONLY the legacy presentational attribute: `<table border="1">` (used heavily by Wikipedia and
  classic HTML) currently produces NO borders, because the `border` attribute is not mapped to CSS.
- Presentational-attribute mapping already exists and is the RIGHT place to do this:
  `src/style/mod.rs` -> `fn collect_presentational_hints(dom, node, ua_rules_count, matched_declarations)`.
  It already maps `width`/`height` (via `map_presentational_dimension`) and img `hspace`/`vspace`.

### Target module (touch ONLY this)

### What to implement (in `collect_presentational_hints`, mirroring the existing width/height hint pattern)
Per the HTML standard's table presentational hints, simplified to our proven paint capability (solid borders):

1. When the element is a `<table>` and has a `border` attribute whose value parses as a u32 `n`:
   - if `n == 0`: do nothing (border="0" explicitly suppresses borders).
   - if `n > 0`: push hint declarations on the table itself:
       * `border-width: <n>px`  (all four sides; you may emit the `border-width` shorthand)
       * `border-style: solid`
       * `border-color: gray`   (UA-ish default; gray is fine)
     Use the same `MatchedDeclaration { specificity:(0,0,0,0), source_order: ua_rules_count, important:false }`
     pattern already used for width/height so author CSS still wins.
     NOTE: the real HTML spec uses `border-style: outset` for the table and `inset` for cells, but our
     paint layer only renders `solid` reliably. Use `solid` and leave:
       `// TODO(spec): table[border] should use outset/inset bevel per HTML spec; paint renders solid only.`

2. When the element is a `<td>` or `<th>` whose NEAREST ANCESTOR `<table>` has a `border` attribute with
   value `n > 0`: push on the cell:
       * `border-width: 1px`
       * `border-style: solid`
       * `border-color: gray`
   Walk ancestors with `dom.parent(node)` until you hit the `<table>` element (stop at the first ancestor
   table; if none has a positive `border` attr, emit nothing). `dom.parent(node) -> Option<NodeId>` exists.
   Reuse `dom.data(id)` to read element name/attrs (see how `collect_presentational_hints` already reads them).
   Add `td`/`th` handling INSIDE the existing `is_presentational_hint_element` gate (td/th already pass it).

Keep it minimal and safe: no `unwrap`/`expect` in src (use `if let`/`match`); parse the attr with
`trimmed.parse::<u32>()` like `map_presentational_dimension` does. A non-numeric `border` (e.g. `border=""`
present-but-empty) per HTML means "1px"; to stay simple, treat a PRESENT-but-non-numeric / empty `border`
attribute as `n = 1` (borders on), and an absent attribute as no hint. Document this with a one-line comment.
